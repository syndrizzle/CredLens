# P2-01 / P2-02 persistence and authentication contract

The user selected FastAPI-managed accounts (`D-03`). P2-01 established internal owner UUIDs and the five financial tables; P2-02 adds `accounts`, `sessions`, `scrypt` password hashing, cookie-backed server sessions, and owner-scoped workspace API/UI integration.

Scope: Alembic migrations (`2b45e0cd055f` and `7c84f91a3d02`), backend persistence and authentication modules (`app/persistence.py`, `app/auth.py`), and protected workspace routes (`app/main.py`) connected to the entry/review UI (`src/features/manual-entry/ManualEntry.tsx`). The stateless `POST /api/validate` and `POST /api/analysis` routes remain available for unauthenticated fictional-data prototype use and Phase 1 tests.

- Owners: internal UUID, creation time; referenced by both accounts and businesses. The demonstration seed (`app/seed.py`) uses a fixed internal owner ID without an `accounts` row and cannot be logged into.
- Accounts: `owner_id` primary/foreign key (`ON DELETE CASCADE`), normalized lowercase email (`unique`, checked for trimmed lowercase and `@`), `password_hash` (`scrypt$16384$8$1$<salt_hex>$<digest_hex>` using Python standard-library `hashlib.scrypt` with 16-byte random salt and `hmac.compare_digest` verification), creation time.
- Sessions: `token_hash` primary key (64-char SHA-256 hex digest of a 256-bit `secrets.token_urlsafe(32)` token; raw token is never stored in PostgreSQL), `owner_id` foreign key (`ON DELETE CASCADE`), `expires_at` (7-day TTL), creation time. Delivered in an `HttpOnly`, `SameSite=Lax`, `Path=/` cookie (`credlens_session`, `Secure` on HTTPS).
- Businesses: owner foreign key, name, INR/standalone basis, input revision.
- Periods: business foreign key, unique start year, unit, exact multiplier, comparability confirmation.
- Figures: period/field key, raw text or null, exact normalized INR numeric or null, manual origin, reviewed flag, revision. Omitted fields remain omitted.
- Analysis runs: business foreign key, input revision, rule version, timestamp, full input snapshot and result JSONB. Results include all six findings, input/revision evidence, reasons, balance checks, and limitations. Decimal values remain strings inside JSON.

Creation is atomic in a caller-owned transaction. Every protected route (`GET /api/auth/session`, `GET /api/businesses`, `POST /api/businesses`, `GET /api/businesses/{business_id}`, `POST /api/businesses/{business_id}/analysis`, `GET /api/analysis-runs/{run_id}`) resolves `owner_id` strictly from the verified server session cookie—never from client-submitted payloads. Unknown and other-owner records return identical `404` responses (`Business not found` or `Analysis not found`). Login failures for unknown emails run a constant-parameter dummy `scrypt` verification and return the same `401` (`Invalid email or password`) as wrong passwords. P2-01/P2-02 create records and analysis runs; correction history, optimistic conflict handling, and superseding outputs remain P2-04.
